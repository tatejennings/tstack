## [0.7.0] — 2026-06-25

### Added
- **`tstack-design` is now wired into the chain as a conditional UI design stage — and its output is consumed downstream instead of being a dead-end.** Previously it produced `docs/2 - Specs/design.md` that no skill read. Now it runs **between `tstack-product` and `tstack-architect`** for products with a consumer-facing UI (a recommendation, never a gate; skipped entirely for headless CLI/library/API): `tstack-product` recommends it for UI products and it recommends `tstack-architect`, while retaining its off-chain "invoke anytime" mode (after roadmap, mid-build). It covers **both UX and visual** design in one skill — no separate UX skill — and owns a new dedicated **`docs/3 - Design/`** folder (parallel to `1 - Discovery` / `2 - Specs`): `design.md` (UX spec — information architecture, navigation structure, user flows, per-screen breakdown with all states — then visual spec — direction, tokens summary, component inventory, accessibility tied to ADR-3), `claude-design-prompts.md` (paste-ready Claude Design hand-off), `design-tokens.json` (**W3C DTCG** — the stack-agnostic machine source; Claude Code translates it to the stack-native config at build time and build verifies contrast against it), `previews/` (HTML mockups / screenshots), and `screens/{name}.md` per-screen breakouts at scale. **Two modes:** *generate* (pick **wireframe vs high-fidelity**, then a **route** — a Claude Design brief [recommended; TStack leans on Claude Design as the quality generator and owns the brief + link-back loop], in-repo HTML previews, or a Figma round-trip when a Figma MCP is connected) and *link-back* (you designed in Claude Design/Figma — the skill records the link/screenshots into a `## Design source` block in `design.md` and prompts to update the linked design whenever the spec later changes). Rewrote SKILL.md + `references/example-output.md`.

### Changed
- **The chain now consumes the design set (closing the old dead-end).** `tstack-architect` reads `docs/3 - Design/design.md` + `design-tokens.json` (optional) and lets them *inform* the frontend-stack ADR and ADR-3 — it reads, never writes the set. `tstack-roadmap` attaches a `docs/3 - Design/design.md — §screen` "Read before starting" pointer to UI-bearing milestones and adds an **honest testability note**: design conformance ("matches the mockup") is a *forbidden* soft criterion; only the command-verifiable a11y slice (axe / contrast-from-tokens / keyboard / reduced-motion) enters "Done when", with visual fidelity left to human review against `previews/`. `tstack-build` verifies that a11y slice with quoted command output, translates `design-tokens.json` into the stack-native config, and is explicitly forbidden from inventing a "matches design.md" PASS-by-assertion.
- **`tstack-product` and `tstack-specify-feature` now route to design for UI work.** Product's handoff forks: UI product → `tstack-design` then `tstack-architect`; headless → straight to `tstack-architect`. Specify-feature includes the `docs/3 - Design/` set in its two-list doc-impact proposal for UI features and recommends `tstack-design` before `tstack-plan-milestone`. Both stay recommend-and-stop.
- **`tstack-ingest` now recognizes pre-existing design material during adoption.** Design docs, HTML app mockups, style guides, design-system/token files, and Figma exports are classified as their own category (no longer lumped toward architect), quarantined as `docs/_adopted/design.draft.md`, and routed to `tstack-design` to ratify into `docs/3 - Design/` — the same quarantine→ratify pattern product uses, applied to the design doc. (A brought-back *link* on an already-adopted project skips ingest and is recorded directly by `tstack-design`.)
- **Reclassified `tstack-design` in CLAUDE.md from off-chain companion to conditional chain participant.** The off-chain companion set is now **two** skills (`tstack-status`, `tstack-wrap`); added a cross-skill contract making `tstack-design` the sole owner of the `docs/3 - Design/` set (architect/roadmap/build read-only) plus the ingest design-staging path, and a numbered-doc-folders editorial note. README updated (chain narrative, a new conditional-design-stage table, the output-structure tree gains `docs/3 - Design/`, lifecycle alt-text).
- **Regenerated `images/lifecycle.jpg`** (via `/refresh-lifecycle`) for design's new role: the chain row now shows `DESIGN` as a dashed "if UI" conditional node between `PRODUCT` and `ARCHITECT`, and the off-chain shelf drops to `STATUS · WRAP · AUTOPILOT`. Updated the `BRANDING.md §11` rendered-graph manifest + composition prompt to match. `agentic-loop.jpg` left unchanged — it depicts only the core setup→plan⇄build loop, which a conditional design stage doesn't alter.
- **Plan artifact renamed `docs/plans/{id}.md` → `docs/plans/{id}-plan.md`** so the plan and the autopilot handoff report form a symmetric, self-describing pair in `docs/plans/` (`m4-plan.md` / `m4-report.md`) instead of the asymmetric `m4.md` / `m4-report.md`. Propagated across the whole contract: `tstack-plan-milestone` (writer + schema + handoff message), `tstack-build` (reader + description + prereq), `tstack-autopilot` (PLAN/RED-TEAM references + description; report path unchanged), `tstack-status` (now globs `docs/plans/*-plan.md` so report files aren't mistaken for planned-ahead work), CLAUDE.md cross-skill contract + on-disk-state invariant, README, the build full-guide source-of-truth header, and the repo-local `/upkeep` A3 check. Historical CHANGELOG sections and dated `reviews/` files left as-is. **Breaking for any consumer repo with already-committed plans** at the old path — rename existing `docs/plans/{id}.md` files to `docs/plans/{id}-plan.md`.

## [0.6.0] — 2026-06-23

### Added
- **`tstack-autopilot` — autonomous milestone runner (opt-in, manual-only).** Generalizes the personal `autopilot` command into a TStack skill: given one milestone ID it plans the milestone, **red-teams the plan with three parallel adversarial agents** (this *replaces* `tstack-plan-milestone`'s human approval gate), builds on a feature branch in an isolated worktree, **verifies against the milestone's "Done when" criteria with quoted command output** (the only authorizing gate — self-review never authorizes), opens a PR, waits for whatever automated reviewer the project uses, triages the feedback, and writes a handoff report. It **never merges** — it hands an open, reviewed PR to a human. Fills TStack's missing unattended mode (BACKLOG #5) without reversing the fresh-session-per-milestone default: it's PR-and-stop, one milestone per run, and never chains. **Manual-only** (`disable-model-invocation: true`) because it mutates git — it must never auto-trigger. **Fail-closed:** refuses unless the tree is clean and on an up-to-date default branch, the M0/i0 infrastructure baseline + CI exist, every "Done when" criterion is command-verifiable, dependencies are all Completed, and no `AGENTS.md`/`CONTRIBUTING` policy forbids autonomous pushes (consumer policy wins). All work happens on a feature branch and the run stops at an open PR — merging stays the human's, with no requirement to enable GitHub branch protection. Tests are append-only (weakening one aborts the run); secret-scan before every push. Markdown-only, no executable code added. Off-chain.
- **`tstack-refactor` — structural/technical refactor iteration skill.** Sibling to `tstack-specify-feature` for changing *how* an existing project is built (migrate a library, split a module, swap a provider, pay down debt) with little or no product change. It demands a solid justification (challenges vibes-based rewrites), judges the change through the **product-goal lens** (updates PRODUCT.md only if the goal genuinely shifted; routes a full pivot back to `tstack-roadmap`), actively **researches the blast radius** in the codebase via `Explore` subagents rather than just asking, records the change as a **superseding ADR** in DECISIONS.md (flip the old one to `Superseded by ADR-N`), and appends **behavior-preserving** ("no regression") milestones — append-only, same testability bar `tstack-roadmap` enforces. **Recommend-and-stop:** it ends by recommending `tstack-plan-milestone` and never starts building. Completes the add/restructure/remove iteration family with the backlogged `tstack-techdebt` (detector) and `tstack-retire` (remove). Ships with `references/example-output.md`.
- **README lifecycle infographic replaces the Mermaid diagram.** The "Lifecycle" section now shows a hand-drawn infographic (`images/lifecycle.jpg`) matching the banner's warm crayon-on-cream style, and "The agentic loop" section gains a matching loop illustration (`images/agentic-loop.jpg`) — both clearer at a glance than the Mermaid flowchart they replace. The images are **AI-generated** (Higgsfield `nano_banana_pro`, mascot locked to the banner via `images/mascot-ref.png` as a reference), so a chain change is a re-generate rather than a redraw. Added `images/BRANDING.md` — the TStack brand & design system (palette, typography, logo, mascot, medium, do/don't, a copy-paste Style Block, and the full regeneration workflow with exact model/settings/prompts, plus a *Rendered graph* manifest recording what the images depict).
- **`/refresh-lifecycle` — repo-local skill to regenerate the README diagrams.** Lives in `.claude/skills/` (outside `skills/`, so it's never shipped — same as `/upkeep` and `/ship`). Runs a no-cost **drift check** first (diffs the live `skills/tstack-*` set and roles against the *Rendered graph* manifest in `BRANDING.md §11`) and only regenerates `lifecycle.jpg`/`agentic-loop.jpg` when a node or role actually changed — pure renames with an unchanged one-word label just update text records. Orchestration-only: it defers to `BRANDING.md §11` for the prompts/model/settings (single source of truth, no forked wording), confirms Higgsfield credit cost before generating, presents variants for the user to pick, post-processes, and updates the manifest + README alt-text + this CHANGELOG. Fail-closed if not in the plugin repo or if the Higgsfield MCP isn't connected. No consumer-facing or plugin behaviour changes.
- **`tstack-refactor` — structural/technical refactor iteration skill.** Sibling to `tstack-specify-feature` for changing *how* an existing project is built (migrate a library, split a module, swap a provider, pay down debt) with little or no product change. It demands a solid justification (challenges vibes-based rewrites), judges the change through the **product-goal lens** (updates PRODUCT.md only if the goal genuinely shifted; routes a full pivot back to `tstack-roadmap`), actively **researches the blast radius** in the codebase via `Explore` subagents rather than just asking, records the change as a **superseding ADR** in DECISIONS.md (flip the old one to `Superseded by ADR-N`), and appends **behavior-preserving** ("no regression") milestones — append-only, same testability bar `tstack-roadmap` enforces. **Recommend-and-stop:** it ends by recommending `tstack-plan-milestone` and never starts building. Completes the add/restructure/remove iteration family with the backlogged `tstack-techdebt` (detector) and `tstack-retire` (remove). Ships with `references/example-output.md`.

### Changed
- **Source-of-truth headers added to the `discover`, `roadmap`, and `build` reference guides.** The `architect` and `product` guides already opened with a `> **Source of truth:** SKILL.md is authoritative…` header, and CLAUDE.md states *every* `full-guide.md` carries one — but the three preserved pre-plugin guides (discover/roadmap/build) had none, making that claim false and leaving the guides most likely to have drifted from their SKILL.md without a "follow SKILL.md if they disagree" pointer. Each now carries a guide-specific header naming its SKILL.md as authoritative and flagging the guide as preserved prose that may lag. Header-only addition — the preserved prose itself is untouched. (Closes the last open thread from the 2026-05-30 advisory review's §3.1 single-source-of-truth recommendation.)
- **TStack no longer suggests or requires branch protection anywhere.** Removed branch protection from `tstack-roadmap`'s mandatory `M0`/`i0` infrastructure baseline — the M0 scope bullet, the "owner configures externally" Done-when group, and the description (and the matching lines in `references/example-output.md` and `references/full-guide.md`). `tstack-build`'s team-PR note no longer references "M0 branch-protection rules"; it just follows whatever review requirements the project records on its own. Enabling branch protection / required reviews is entirely the user's repo-settings call — the framework only honors it if the user records it themselves (planning, PRODUCT/DECISIONS docs, AGENTS.md, CONTRIBUTING), and never proposes it as a default. M0 remains mandatory for CI, secrets, deployment skeleton, observability, lint, and test runner.
- **Renamed two skills for explicitness: `tstack-plan` → `tstack-plan-milestone`, `tstack-specify` → `tstack-specify-feature`.** The two vaguest names now name their object ("plan *what*? specify *what*?"). Invocation changes accordingly (`/tstack-plan-milestone`, `/tstack-specify-feature`); all live cross-references were updated (handoff prose, README diagram/tables/tree, CLAUDE.md contracts and conventions, the `/upkeep` skill). Historical `reviews/` files and prior CHANGELOG version sections were left untouched (they're a dated record). The plan artifact path stays `docs/plans/{id}.md` — named for "plans", not the skill.
- **Regenerated `images/lifecycle.jpg` for the current 13-skill chain.** Via `/refresh-lifecycle`: the infographic now shows two iteration return arrows into PLAN — `SPECIFY · add` and `REFACTOR · restructure` (previously just one) — picking up the new `tstack-refactor` skill; the renamed `tstack-plan-milestone`/`tstack-specify-feature` nodes keep their unchanged one-word labels (`PLAN`/`SPECIFY`). `agentic-loop.jpg` was left as-is (it depicts only the 6-step main chain + plan ⇄ build loop, which didn't change). Updated the *Rendered graph* manifest and composition prompt in `BRANDING.md §11` and the README lifecycle alt-text to match.

## [0.5.0] — 2026-06-21

### Changed
- **iOS-aware structure and infrastructure milestones.** `tstack-architect` still emits a complete, buildable repo tree but now labels it a *"baseline an implementer may restructure (record as an ADR + update this section)"* rather than a fixed contract — never "TBD", never omitted (feedback item **T2**). `tstack-roadmap` now splits every infrastructure milestone's "Done when" into two labeled groups — ***implementation satisfies*** (provable by the build/test/lint/CI run) vs ***owner configures externally*** (GitHub/host/Apple console settings, attested not command-checked) — so a milestone stops reading as "not done" because of a provider toggle the code can't flip, and a real implementation gap can't hide behind one (**T3**). For iOS-primary projects, `tstack-roadmap` now emits the mandatory baseline as **`i0 — iOS infrastructure baseline`** (the iOS analog of M0: `xcodebuild`/`swift test`/SwiftLint in CI, signing/secrets, archivable app skeleton, crash reporting, test runner), described as a normal hand-implementable milestone and using the same implementation-vs-external split (**T6**). `tstack-architect` now gives **each deployable app its own top-level folder at the repo root** (`web/`, `apple/`, `android/`) — not nested under an `apps/` wrapper, and never the lone app dumped loose at the root — with shared cross-platform code under `shared/`/`packages/`. This holds even for a single app, so expanding to a second platform later is additive, not a restructure (platform-at-root suits T-Stack's typically-polyglot projects, where a Swift app and a web app share no workspace tool and an `apps/` parent only adds nesting). The Apple folder is named `apple/` rather than `ios/` since one Swift codebase often spans iOS/iPadOS/macOS/watchOS. The Slink example across all skills' `references/example-output.md` is updated to root-level folders to match. The (web-only) Slink example also gains two compact **iOS reference snippets** — an `apple/` tree fragment in the architect example and an `i0 — iOS infrastructure baseline` milestone in the roadmap example (both clearly marked as iOS reference, not part of Slink's actual sequence) — so the new iOS folder convention and `i0` split have a worked example without making Slink itself multi-platform. Updates both skills' SKILL.md, `references/full-guide.md`, and `references/example-output.md`.
- **`tstack-architect` now frames foundational and stack ADRs as authoritative *but revisable*.** Every ADR (the four foundational ones *and* every tech-stack ADR) now carries a mandatory, prominent `Revisit when:` trigger — previously only tech-stack ADRs did. DECISIONS.md opens with a standard **"How decisions change here"** header documenting a low-ceremony supersession path (add a new ADR that supersedes the old, flip the old one's status to `Superseded by ADR-N`, update affected docs) and an **append-only numbering rule** (next ADR = highest existing + 1, never renumbered or reused) — so a later implementer (another agent, a teammate, or future-you adopting a DI framework) can override a default cleanly without colliding with a future T-Stack ADR or reading like rule-breaking. CONVENTIONS.md generation now separates genuine anti-patterns (correctness/security/bug-class rules) from *project choices* (stack/structure decisions), which are stated as defaults-with-rationale that point to their ADR rather than branded inviolable prohibitions. Addresses feedback items **T1** and **T5**. Updates SKILL.md, `references/full-guide.md`, and `references/example-output.md`.

## [0.4.0] — 2026-06-20

### Added
- **`tstack-ingest` — adoption on-ramp for projects that already have docs.** Reads a user's pre-existing material (a PRD, discovery notes, design/architecture docs in any format), reflects intent back to catch a stale-after-pivot doc, classifies coverage (Present / Thin / Missing with named gaps), and distills it into an *unratified draft* at `docs/_adopted/` — never a canonical doc. `tstack-product` then authors `docs/PRODUCT.md` from the draft through its existing requirements gate and deletes the draft on save, so adopted content still passes verification before entering the loop. Foreign technical/design material is staged as `docs/_adopted/*-notes.md` and routed to `tstack-architect` (which asks its four ADR questions fresh — adoption can't smuggle a project past them). It's a **chain on-ramp** (required handoff to `tstack-product`), not an off-chain skill.

### Changed
- **`tstack-product` is adoption-aware.** If `docs/_adopted/PRODUCT.draft.md` exists, it ratifies the draft through its full gate (resolving every `## Open gaps` item) instead of re-interviewing, and removes the draft on save. Remains the sole author of `PRODUCT.md`.
- **`tstack-discover` forwards existing docs to `tstack-ingest`.** Its old "distill existing material into business-brief.md in one pass" branch is removed; when the user already has docs (or points discover at a file/folder), discover detects and hands off to ingest rather than distilling itself — a single home for adoption, no trigger collision.
- **CLAUDE.md** records the adoption contract (`tstack-ingest` writes only to `docs/_adopted/`, never canonical files) and classifies ingest as a chain on-ramp distinct from the three off-chain companions.
- **README, `plugin.json`, `marketplace.json`** updated for the new skill (lifecycle diagram on-ramp node, skill table, repo-layout tree, and count wording).

## [0.3.2] — 2026-06-14

### Changed
- **Repositioned around the agentic loop (docs only, no behavior change).** README gains a "The agentic loop" section naming the three properties that make TStack's loop trustworthy — durable on-disk context, verification as the engine, and a fresh session per iteration — with an honest note on the "loop engineering" / context-engineering / harness terminology. CLAUDE.md records the same three as **design invariants** future edits must preserve. Also fixed a stale "two off-chain companions" reference (now three — includes `tstack-wrap`).

## [0.3.1] — 2026-06-14

### Changed
- **Per-milestone loop now defaults to a fresh session per step instead of chaining in one window.** `tstack-plan` ends after writing the plan and recommends building in a fresh session (no rolling straight into `tstack-build`); `tstack-build` ends after shipping and recommends planning the next milestone in a fresh session (no auto-advancing). The on-disk plan (`docs/plans/{id}.md`) + ROADMAP status already carry all state across the boundary, so nothing is lost. Same-session work is still allowed when the user explicitly asks. Addresses user-reported context bloat from the skills auto-chaining plan→build→next-milestone. README Quick Start updated to match.

## [0.3.0] — 2026-06-14

### Added
- `tstack-wrap` — optional, off-chain session doc-sweep skill. At the end of a session it sweeps the work just done (conversation + `git log` + `docs/`) for undocumented decisions, tradeoffs, gotchas, and operational events (stale branches, deferred criteria, manual steps), then writes each genuine gap to its right home — a dated ADR in `DECISIONS.md`, a pattern in `CONVENTIONS.md`, a code comment, or `ROADMAP.md`'s Status section. It **does not commit**, never adds or renumbers roadmap milestones, and routes new scope to `tstack-specify`. Complements `tstack-status` (which only *detects* drift, read-only) by *closing* the gap. Addresses the doc-staleness risk surfaced by user feedback. Manual by default; the README documents an optional opt-in `Stop` hook for consumers who want a wrap-up nudge at session end.

## [0.2.0] — 2026-05-30

### Added
- `tstack-design` — optional, off-chain skill that produces a design/UX spec (`docs/2 - Specs/design.md`) plus ready-to-paste prompts and context for Claude Design. Invokable at any point; not part of the chain.
- `tstack-status` — optional, off-chain, read-only inspector. Reports project status, planned-ahead plans, missing mandatory docs, and **doc drift** (e.g. PRODUCT.md edited after ROADMAP.md's last sync). Writes nothing.
- Foundational ADRs in `tstack-architect` (security, observability, accessibility, privacy) + optional AI/LLM ADR; mandatory `TESTING.md` and `DECISIONS.md` at every right-sizing level.
- `M0 — Infrastructure baseline` mandate in `tstack-roadmap` (refuses to save a roadmap without it).
- Eval-based AI/LLM acceptance criteria (eval set + quality bar + fallback) in `tstack-product`; deep acceptance-criteria guidance incl. the subjectivity question.

### Changed
- **Plan artifact** persisted in-repo at `docs/plans/{id}.md` (`tstack-plan` writes, `tstack-build` reads). Committing is a manual step so planned-ahead milestones can be handed to a cloud agent.
- **`ROADMAP.md` ownership contract:** `tstack-roadmap` regenerates and carries a `Docs last synced:` marker; `tstack-specify` is append-only (never renumbers).
- **`AGENTS.md` ownership:** `tstack-architect` owns the file; `tstack-roadmap`/`tstack-build` update only the `## Current Focus` block.
- `tstack-roadmap` validates "Done when" testability at write time; description now lists `CONVENTIONS.md`.
- `tstack-product` flags AI features early and requires a completion sign-off before saving.
- `tstack-architect` asks the team's ecosystem before proposing a stack, dates each tech-stack ADR, and consolidates related choices into one ADR.
- `tstack-build` gained a controlled criterion-waiver policy and a concrete team-PR flow.
- `tstack-discover` gained a when-NOT-to-run redirect, a brief-ready gate, and an operationalized no-WebSearch fallback.
- Standardized the fresh-session threshold across the setup-chain handoffs.
- De-staled the `architect` `full-guide.md` (added TESTING.md + foundational ADRs, fixed the opinionated-default contradiction, removed dead pre-plugin file references) and thickened the `product` `full-guide.md`; both now name SKILL.md as the source of truth.
