# Slink — Product Requirements (v1.0)

## Product Overview

Slink is a link shortener for solo and small-team content creators (newsletter writers, podcasters, YouTubers). v1 ships custom-branded domains, per-link analytics, and AI-suggested slugs. Target: 50 paying Pro users in first 3 months.

## Target User

**Primary persona — "Riley, newsletter writer"**
- 5k–50k subscribers; weekly cadence; writes 5–20 links per issue
- Uses Beehiiv or Substack; pastes raw URLs today
- Pain: bit.ly looks unprofessional in newsletter; typing custom slugs is tedious; can't tell which links subscribers actually click
- Will pay $9/mo if it saves her 30 min/week

## Features

### F-1: Account Creation & Branded Domain Setup

Riley signs up via Clerk (Google or email). On first login, she's prompted to add a custom domain or use `slink.app` (default). If custom: she enters `links.riley.fm`, sees the required CNAME record, adds it in her DNS, and clicks "Verify." Verification polls every 30s for up to 10 min.

**Acceptance criteria (Given/When/Then):**
- Given a new signup, when they reach onboarding, then they see "Use slink.app" and "Add custom domain" as equal-weight options.
- Given a custom domain with a correct CNAME, when the user clicks "Verify," then verification succeeds within 60s.
- Given a CNAME pointing elsewhere, when the user clicks "Verify," then the UI shows what was expected vs. found and the exact CNAME record to add.
- **Accessibility:** the verification flow is fully keyboard-navigable; status updates are announced via `aria-live`; meets WCAG 2.1 AA on contrast and focus order.

### F-2: Link Creation with Optional AI Slug Suggestion

Riley pastes a URL. The system fetches the page's `<title>` and `<meta description>` and proposes 3 slug options. She can pick one, type her own, or accept a random auto-generated slug.

**Acceptance criteria (mixed: deterministic + AI):**

*Deterministic parts:*
- Given a logged-in Free-tier user at the link limit (5/mo), when they try to create a 6th link, then they see a "Plan limit reached" message with an upgrade CTA. No link is created.
- Given a slug that's already taken on the same domain, when the user submits, then they see "That slug is taken on links.riley.fm — try another" and the form retains other fields.

*AI parts (eval-based):*
- **Eval set:** `evals/slug-suggestions-v1.jsonl` — 100 URLs spanning newsletters, podcasts, YouTube, blog posts; each with 3 hand-labeled "good" slug examples.
- **Quality bar:** ≥75% of suggestions rated "acceptable or better" by the grader prompt in `evals/grader.md`. Top-1 (the first of 3) ≥60% acceptance.
- **Fallback:** On model error, timeout >4s, content filter trip, or empty/garbage suggestions: show the manual slug input with placeholder text "e.g. `issue-47-ai-roundup`" — never show "AI failed" to the user.

### F-3: Per-Link Analytics

Riley clicks a link in her list, sees a detail page with: total clicks, unique visitors, time-series chart (24h / 7d / 30d), referrer breakdown (top 10), country breakdown.

**Acceptance criteria:**
- Given a link with clicks from 3 distinct IPs (hashed), when the user opens analytics, then "Unique visitors: 3" is shown.
- Given a link with a `Referer` of `https://riley.beehiiv.com/p/issue-47`, when displayed in the referrer breakdown, then the host is shown as `riley.beehiiv.com` (path stripped).
- **Performance:** analytics page loads in <800ms p95 for links with <100k clicks.
- **Privacy:** IPs are SHA-256 hashed with a daily-rotating salt before storage; raw IP never persisted. Test: query the events table and confirm no field looks IP-like.

### F-4: Redirect Service

The actual short-link redirect. Hot path. Lives on Cloudflare Workers (per ARCHITECTURE.md).

**Acceptance criteria:**
- Given a request to `links.riley.fm/abc123`, when the slug resolves, then a `302` is returned with the correct `Location` header in <50ms p95 globally.
- Given a request to a slug that doesn't exist, when resolved, then a `404` is returned with a branded "Link not found" page.
- Given a request from an EU IP, when handled, then no PII is logged; only the hashed IP, country code, referrer host, and timestamp are recorded.

## Edge Cases & Error States

- Destination URL invalid → reject at creation with specific error (not "invalid input")
- DNS verification timeout (>10 min) → user can retry without recreating the domain
- LLM rate-limited → AI slug button shows "AI suggestions paused, try again in 60s"
- Click on archived link → 410 Gone (not 404) so analytics can distinguish "never existed" from "removed"
- Account deletion → all PII deleted within 30 days; aggregated click counts (non-PII) retained for product analytics
- Free-tier link inactivity (no clicks in 180 days) → flagged in UI; archived automatically at 365 days (with email warnings at 270 and 350 days)

## Out of Scope (v1)

- Team workspaces (post-launch, via tstack-specify)
- Native mobile apps
- Real-time analytics
- A/B testing of destinations
- Bulk import from competitors
- Custom 404 pages per domain (single branded page for v1)
- Webhooks / API beyond CSV export

## UI/UX

- Two main screens: **Dashboard** (link list + search + create) and **Link Detail** (analytics).
- Onboarding: 3 steps max — sign up → choose domain → create first link. No carousel walkthroughs.
- Empty states are real (illustration + concrete CTA), not generic.
- Mobile: responsive, dashboard usable from phone for click-monitoring; link creation is desktop-primary.
